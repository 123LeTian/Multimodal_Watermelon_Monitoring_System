# 大棚西瓜多模态数据交接规范表

## 1. 文档目的

本文档用于规定未来真实数据交接时必须遵守的数据格式、文件结构、字段命名、标签编码和验收标准。

当前项目尚未采集真实数据，因此本规范先固定数据格式。后续数据同学采集、整理和标注数据时，必须按照本文档交付，保证模型代码可以直接读取数据并进行训练、验证、测试和推理。

## 2. 数据用途

本数据集用于训练大棚西瓜多模态生长状态评估模型。

模型输入：

| 输入项 | 说明 |
| --- | --- |
| 西瓜图片 | 拍摄当前植株、叶片、花、果实或整体长势的图像 |
| 环境时序数据 | 图片拍摄时间点之前 24 小时内的空气温度、土壤湿度、光照和 pH 数据 |

模型输出：

| 输出字段 | 输出名称 | 任务类型 |
| --- | --- | --- |
| `growth_stage` | 生长阶段 | 6 类分类 |
| `health_level` | 健康等级 | 4 类分类 |
| `maturity_level` | 成熟度等级 | 4 类分类 |
| `abnormal_alert` | 生长异常预警 | 2 类分类 |

## 3. 交付目录结构

数据同学交付真实数据时，应提供一个完整的 `dataset/` 文件夹，结构如下：

```text
dataset/
├─ images/
│  ├─ IMG_000001.jpg
│  ├─ IMG_000002.jpg
│  └─ ...
├─ environment.csv
├─ labels.csv
├─ split.csv
└─ README.md
```

各文件作用如下：

| 文件或文件夹 | 是否必须 | 说明 |
| --- | --- | --- |
| `images/` | 必须 | 存放所有西瓜图片 |
| `environment.csv` | 必须 | 存放所有环境传感器时序数据 |
| `labels.csv` | 必须 | 存放每张图片对应的 4 个模型标签 |
| `split.csv` | 必须 | 存放训练集、验证集、测试集划分 |
| `README.md` | 必须 | 说明数据来源、采集时间、采集地点、传感器信息和标注人员 |

## 4. 图片数据规范

### 4.1 图片格式

图片文件必须满足：

1. 格式为 `.jpg`、`.jpeg` 或 `.png`。
2. 图片必须能正常打开，不能损坏。
3. 图片内容应尽量包含西瓜植株、叶片、花、果实或整体长势。
4. 图片应避免严重模糊、过曝、欠曝、遮挡和无关背景过多。

### 4.2 图片命名

图片统一命名为：

```text
IMG_000001.jpg
IMG_000002.jpg
IMG_000003.jpg
```

命名要求：

1. `image_id` 必须唯一。
2. 文件名建议使用 `IMG_六位数字` 格式。
3. 不要在文件名中使用中文、空格、括号或特殊符号。
4. 图片文件名必须与 `labels.csv` 中的 `image_path` 对应。

### 4.3 图片路径

图片路径在 `labels.csv` 中统一写成相对路径，例如：

```text
images/IMG_000001.jpg
```

不要写成本机绝对路径，例如：

```text
D:/Project/watermelon_monitoring/dataset/images/IMG_000001.jpg
```

## 5. 环境数据规范

环境数据统一存放在 `environment.csv` 中。

### 5.1 字段要求

`environment.csv` 必须包含以下字段：

| 字段名 | 类型 | 是否必须 | 说明 | 示例 |
| --- | --- | --- | --- | --- |
| `timestamp` | 字符串 | 必须 | 环境数据采集时间 | `2026-09-21 08:00:00` |
| `temperature` | 数值 | 必须 | 空气温度，单位摄氏度 | `28.5` |
| `soil_humidity` | 数值 | 必须 | 土壤湿度，单位百分比 | `65.2` |
| `light` | 数值 | 必须 | 光照强度，单位按实际传感器记录 | `12000` |
| `ph` | 数值 | 必须 | 土壤 pH | `6.8` |

### 5.2 示例

```csv
timestamp,temperature,soil_humidity,light,ph
2026-09-21 08:00:00,28.5,65.2,12000,6.8
2026-09-21 08:10:00,28.7,64.9,12130,6.8
2026-09-21 08:20:00,28.9,64.5,12320,6.7
```

### 5.3 时间格式

所有时间字段统一使用以下格式：

```text
YYYY-MM-DD HH:MM:SS
```

示例：

```text
2026-09-21 08:30:00
```

要求：

1. 使用 24 小时制。
2. 不使用中文日期格式。
3. 不使用斜杠日期格式。
4. 所有时间应处于同一时区。

## 6. 标签数据规范

标签数据统一存放在 `labels.csv` 中。

### 6.1 字段要求

`labels.csv` 必须包含以下字段：

| 字段名 | 类型 | 是否必须 | 说明 | 示例 |
| --- | --- | --- | --- | --- |
| `image_id` | 字符串 | 必须 | 图片唯一编号，不带扩展名 | `IMG_000001` |
| `image_path` | 字符串 | 必须 | 图片相对路径 | `images/IMG_000001.jpg` |
| `capture_time` | 字符串 | 必须 | 图片拍摄时间 | `2026-09-21 08:30:00` |
| `growth_stage` | 整数 | 必须 | 生长阶段标签 | `4` |
| `health_level` | 整数 | 必须 | 健康等级标签 | `1` |
| `maturity_level` | 整数 | 必须 | 成熟度等级标签 | `1` |
| `abnormal_alert` | 整数 | 必须 | 生长异常预警标签 | `1` |

### 6.2 示例

```csv
image_id,image_path,capture_time,growth_stage,health_level,maturity_level,abnormal_alert
IMG_000001,images/IMG_000001.jpg,2026-09-21 08:30:00,4,1,1,1
IMG_000002,images/IMG_000002.jpg,2026-09-21 09:00:00,4,0,1,0
IMG_000003,images/IMG_000003.jpg,2026-09-21 09:30:00,5,0,2,0
```

## 7. 标签编码规范

### 7.1 生长阶段 `growth_stage`

| 标签值 | 标签名称 |
| --- | --- |
| 0 | 发芽期 |
| 1 | 伸蔓期 |
| 2 | 开花期 |
| 3 | 坐果期 |
| 4 | 膨大期 |
| 5 | 成熟期 |

### 7.2 健康等级 `health_level`

| 标签值 | 标签名称 |
| --- | --- |
| 0 | 正常 |
| 1 | 轻微异常 |
| 2 | 中度异常 |
| 3 | 严重异常 |

### 7.3 成熟度等级 `maturity_level`

| 标签值 | 标签名称 |
| --- | --- |
| 0 | 未成熟 |
| 1 | 接近成熟 |
| 2 | 成熟 |
| 3 | 过熟 |

### 7.4 生长异常预警 `abnormal_alert`

| 标签值 | 标签名称 |
| --- | --- |
| 0 | 无异常 |
| 1 | 有异常 |

注意：`abnormal_alert` 只表示西瓜生长异常，例如长势弱、叶片异常、果实发育异常、疑似病害、成熟异常等。传感器损坏、数据缺失、通信失败、设备离线等问题不属于该标签，应在数据清洗阶段处理。

## 8. 图片与环境数据对齐规则

每张图片需要匹配其拍摄时间点之前 24 小时内的环境数据。

例如：

```text
图片拍摄时间：2026-09-21 08:30:00
环境数据窗口：2026-09-20 08:30:00 至 2026-09-21 08:30:00
```

对齐要求：

1. 以 `labels.csv` 中的 `capture_time` 作为图片拍摄时间。
2. 从 `environment.csv` 中选取 `capture_time` 前 24 小时内的数据。
3. 环境数据窗口包含空气温度、土壤湿度、光照、pH 四个字段。
4. 如果前 24 小时环境数据为空，该样本不能直接用于训练。
5. 如果前 24 小时环境数据过少，应在数据检查报告中标记。

## 9. 数据集划分规范

数据集划分结果统一存放在 `split.csv` 中。

### 9.1 字段要求

| 字段名 | 类型 | 是否必须 | 说明 | 示例 |
| --- | --- | --- | --- | --- |
| `image_id` | 字符串 | 必须 | 图片唯一编号 | `IMG_000001` |
| `split` | 字符串 | 必须 | 数据划分类型 | `train` |

### 9.2 示例

```csv
image_id,split
IMG_000001,train
IMG_000002,val
IMG_000003,test
```

### 9.3 划分要求

`split` 只能取以下三个值：

| 值 | 含义 |
| --- | --- |
| `train` | 训练集 |
| `val` | 验证集 |
| `test` | 测试集 |

建议比例：

| 数据集 | 建议比例 |
| --- | --- |
| 训练集 | 70% |
| 验证集 | 15% |
| 测试集 | 15% |

注意：

1. 同一植株、同一天连续拍摄的高度相似图片，不建议随机分散到训练集和测试集。
2. 如果有不同大棚、不同区域或不同批次，优先按批次、日期、植株或区域划分，避免数据泄漏。
3. 测试集一旦确定，不要在调参过程中反复修改。

## 10. 数据质量要求

### 10.1 图片质量

图片应满足：

1. 图片能正常打开。
2. 图片主体与西瓜生长相关。
3. 图片不应严重模糊、过曝、欠曝或遮挡。
4. 图片路径与 `labels.csv` 中记录一致。

### 10.2 环境数据质量

环境数据应满足：

1. `timestamp` 不能为空。
2. `temperature`、`soil_humidity`、`light`、`ph` 不能为空。
3. 同一时间戳不应出现重复记录。
4. 数值明显异常时，应在数据清洗阶段处理并记录。

建议合理范围如下，超过范围的数据不一定立即删除，但必须检查：

| 字段 | 建议检查范围 |
| --- | --- |
| `temperature` | 0 到 60 |
| `soil_humidity` | 0 到 100 |
| `light` | 大于等于 0 |
| `ph` | 0 到 14 |

### 10.3 标签质量

标签应满足：

1. 每张图片必须有 4 个标签。
2. 标签值必须使用整数编码。
3. 标签值必须在本规范规定范围内。
4. 不能使用中文标签、英文单词或空白值替代数字编码。
